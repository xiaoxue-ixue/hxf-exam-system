## 一、作业目的

本次作业面向「在线考试系统」的后台管理模块，目标是打通 **登录鉴权 → 用户管理增删改查 → 前后端联调** 这条完整链路，解决以下三个实际问题：

1. **后台不能被匿名访问。** 用户管理涉及增删改，必须有可靠的身份认证机制，而不能像原型阶段那样在前端写死账号密码。为此需要实现基于 JWT 的无状态令牌认证，并在后端对每个受保护接口做校验。
2. **用户数据要能高效检索与维护。** 系统用户会随学期增长，列表必须支持分页与按条件模糊搜索；同时要支持新增、编辑、启停用，满足管理员日常运维需要。
3. **删除用户不能物理删除。** 历史考试记录、成绩记录仍引用该用户，直接 `DELETE` 会造成外键悬空与数据不可追溯。因此采用逻辑删除，保留记录并把标记位置 1。

通过本次作业，掌握以下技术要点：RESTful 接口设计规范、统一响应体与全局异常处理、MyBatis-Plus 分页插件与条件构造器、`@TableLogic` 逻辑删除、Spring Security 过滤器链与 JWT 鉴权、Vue 3 + Axios 封装与 Element Plus 表格组件联调。

## 二、作业内容与要求

### 2.1 功能要求（7 个接口）

| 编号 | 功能 | 方法与路径 | 关键要求 |
|---|---|---|---|
| U1 | 分页查询用户列表 | `GET /user/page` | `pageNum` 默认 1、`pageSize` 默认 10；返回 `records` / `total` / `pages` |
| U2 | 条件搜索 | `GET /user/page?username=&realName=` | 按用户名、姓名**模糊**匹配，参数为空时不过滤 |
| U3 | 新增用户 | `POST /user` | 用户名唯一，重复时返回 `code=500`、`message=用户名已存在`；`status` 缺省为 1；密码以 BCrypt 加密存储 |
| U4 | 编辑用户 | `PUT /user` | 更新姓名与状态；传入 `roleId` 时同步维护角色关联表（先删后插）；**不传 `roleId` 时关联表不得被清空** |
| U5 | 删除用户 | `DELETE /user/{id}` | 逻辑删除，`deleted` 置 1，记录保留；重复删除同一 id 仍返回成功（幂等） |
| U6 | 启用 / 禁用 | `PUT /user/{id}/status/{status}` | `status=0` 禁用、`status=1` 启用 |
| 辅助 | 角色下拉 | `GET /user/roles` | 返回 ADMIN / TEACHER / STUDENT 三条 |

### 2.2 通用要求

- 除 `POST /auth/login` 与 `/hello` 外，**所有接口必须携带** `Authorization: Bearer <token>`，否则拒绝访问。
- 统一响应格式 `{code, message, data}`，`code == 200` 表示业务成功。
- 业务异常（如用户名重复、用户不存在）由全局异常处理器统一转成 `{code, message}`，不向前端抛 500 堆栈。
- 前端需完成用户列表页的表格展示、搜索、新增、编辑、删除、启停用，并接入真实后端接口。

## 四、程序设计思路

### 4.1 总体架构与请求链路

系统采用前后端分离架构，请求链路如下：

```
浏览器（Vue 3 + Element Plus，localhost:5173）
   │  Axios 实例 baseURL = "/api"
   ▼
Vite 开发服务器代理：/api → http://localhost:8080，并 rewrite 去掉 /api 前缀
   │
   ▼
Spring Boot（内嵌 Tomcat，8080）
   ├─ JwtAuthenticationFilter   解析 Authorization 头，验签，写入 SecurityContext
   ├─ SecurityConfig            放行 /auth/login、/hello，其余要求已认证
   ├─ Controller                接收请求、参数绑定、返回统一响应体 R
   ├─ Service                   业务逻辑与事务（用户、角色联合维护）
   └─ Mapper（MyBatis-Plus）    分页、条件构造、逻辑删除
   │
   ▼
MySQL 数据库 hxf_exam（sys_user / sys_role / sys_user_role）
```

### 4.2 鉴权设计：JWT 无状态认证

前后端分离且后期要接入小程序与 App，跨域场景下 Cookie 不便携带，因此选用 JWT 令牌方案。流程为：

1. 客户端 `POST /auth/login` 提交账号密码；
2. 服务端用 `BCryptPasswordEncoder.matches` 校验密码（数据库中只存哈希，不存明文）；
3. 查 `sys_user_role` 与 `sys_role` 得到角色编码（ADMIN / TEACHER / STUDENT）；
4. `JwtUtil` 用 HS384 算法签发令牌，Payload 携带 `sub`（用户名）、`role`（角色编码）、`exp`（24 小时）；
5. 客户端保存令牌，此后每个请求在请求头携带 `Authorization: Bearer <token>`；
6. `JwtAuthenticationFilter` 拦截请求，取出令牌验签，解析出角色并拼成 `ROLE_ + 角色编码` 写入 `SecurityContextHolder`；
7. `SecurityConfig` 中的 `anyRequest().authenticated()` 依据认证结果决定放行或拒绝。

> 注意：JWT 的 Payload 只是 Base64 编码而非加密，任何人都能解开阅读，因此**绝不能把密码放进去**。

### 4.3 分页与条件查询

- 在 `MybatisPlusConfig` 中注册 `PaginationInnerInterceptor(DbType.MYSQL)`，否则 `selectPage` 不会真正生成 `LIMIT`。
- 查询条件封装在 `UserQueryDTO`，通过 `LambdaQueryWrapper` 动态拼接：用 `StringUtils.hasText()` 判断参数是否为空，非空才追加 `like` 条件，从而「有参数就过滤、没参数就查全部」。
- 由于前端需要展示角色名称，而角色信息存在关联表中，因此不能直接返回 `SysUser` 实体。做法是先查出 `Page<SysUser>`，再逐条转换为 `UserVO` 并在转换时查一次关联表补上 `roleCode` / `roleName`。
- **关键坑点**：`Page<SysUser>` 与 `Page<UserVO>` 泛型不同，不能直接强转。新建 `Page<UserVO>` 时必须把 `total` 一并传入，否则前端分页组件拿不到总条数，分页条会失效。

### 4.4 角色关联的维护：先删后插

`sys_user_role` 是用户与角色的多对多中间表，一个用户对应一条关联记录。编辑用户时若前端传入了 `roleId`，处理策略是：

1. `DELETE FROM sys_user_role WHERE user_id = ?` 清掉旧关联；
2. `INSERT` 一条新关联。

这样「首次分配角色」和「修改角色」可以复用同一段代码，无需先判断记录是否存在。而 `roleId` 为 `null` 时整段逻辑直接跳过，避免前端只改姓名时误把角色清空——这是本次设计中最容易被写错的地方。

### 4.5 逻辑删除

`SysUser` 的 `deleted` 字段标注了 `@TableLogic`。标注之后：

- `deleteById(id)` 实际执行 `UPDATE sys_user SET deleted = 1 WHERE id = ?`；
- 所有查询自动追加 `deleted = 0` 条件，被删用户不会出现在列表中；
- 重复删除同一个 id 时，SQL 影响行数为 0，但不报错，业务上表现为幂等。

采用逻辑删除而非物理删除，是因为该用户可能已经产生考试与答题记录，物理删除会使历史数据失去归属。

### 4.6 前端实现要点

- `utils/request.js` 创建 Axios 实例，`baseURL` 设为 `/api`；**请求拦截器**自动从 `localStorage` 读取 token 注入 `Authorization` 头；**响应拦截器**统一判断 `code`，非 200 时用 `ElMessage` 弹出后端返回的 `message`，成功时直接返回 `data`，业务代码无需重复解包。
- `vite.config.js` 配置 `server.proxy`，把 `/api` 转发到 `8080` 并去掉 `/api` 前缀，从而绕开浏览器同源限制。
- `views/user/UserList.vue` 使用 `el-table` 展示列表、`el-pagination` 分页、`el-dialog` 完成新增与编辑表单，操作列提供编辑、启停用、重置密码、删除四个按钮。

### 代码 1　JWT 认证过滤器

```java
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    private final JwtUtil jwtUtil;

    public JwtAuthenticationFilter(JwtUtil jwtUtil) {
        this.jwtUtil = jwtUtil;
    }

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain chain)
            throws ServletException, IOException {
        String header = request.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            String token = header.substring(7);
            try {
                Claims claims = jwtUtil.parseToken(token);
                String username = claims.getSubject();
                String role = claims.get("role", String.class);
                // 角色加 ROLE_ 前缀：Spring Security 约定 hasRole("ADMIN") 实际比对 ROLE_ADMIN
                var auth = new UsernamePasswordAuthenticationToken(
                        username, null,
                        List.of(new SimpleGrantedAuthority("ROLE_" + role)));
                SecurityContextHolder.getContext().setAuthentication(auth);
            } catch (JwtException | IllegalArgumentException e) {
                // token 无效，不设置认证信息
            }
        }
        chain.doFilter(request, response);
    }
}
```

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    private final JwtAuthenticationFilter jwtAuthenticationFilter;

    public SecurityConfig(JwtAuthenticationFilter jwtAuthenticationFilter) {
        this.jwtAuthenticationFilter = jwtAuthenticationFilter;
    }

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
                .csrf(csrf -> csrf.disable())
                .cors(Customizer.withDefaults())
                .sessionManagement(sm -> sm.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
                .authorizeHttpRequests(auth -> auth
                        .requestMatchers("/auth/login", "/hello").permitAll()
                        .anyRequest().authenticated()
                )
                .addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
```

### 代码 4　用户业务实现（分页、增删改、角色维护）

```java
@Service
public class UserServiceImpl implements UserService {

    private final SysUserMapper sysUserMapper;
    private final SysRoleMapper sysRoleMapper;
    private final SysUserRoleMapper sysUserRoleMapper;
    private final PasswordEncoder passwordEncoder;

    public UserServiceImpl(SysUserMapper sysUserMapper,
                           SysRoleMapper sysRoleMapper,
                           SysUserRoleMapper sysUserRoleMapper,
                           PasswordEncoder passwordEncoder) {
        this.sysUserMapper = sysUserMapper;
        this.sysRoleMapper = sysRoleMapper;
        this.sysUserRoleMapper = sysUserRoleMapper;
        this.passwordEncoder = passwordEncoder;
    }

    @Override
    public Page<UserVO> page(UserQueryDTO query) {
        Page<SysUser> page = new Page<>(query.getPageNum(), query.getPageSize());
        LambdaQueryWrapper<SysUser> wrapper = new LambdaQueryWrapper<>();
        wrapper.like(StringUtils.hasText(query.getUsername()), SysUser::getUsername, query.getUsername())
                .like(StringUtils.hasText(query.getRealName()), SysUser::getRealName, query.getRealName())
                .orderByDesc(SysUser::getId);
        Page<SysUser> userPage = sysUserMapper.selectPage(page, wrapper);

        // 泛型要从 SysUser 换成 UserVO，新建 Page 时 total 必须手动搬过去
        Page<UserVO> voPage = new Page<>(userPage.getCurrent(), userPage.getSize(), userPage.getTotal());
        List<UserVO> records = userPage.getRecords().stream()
                .map(this::toVO)
                .collect(Collectors.toList());
        voPage.setRecords(records);
        return voPage;
    }

    private UserVO toVO(SysUser user) {
        UserVO vo = new UserVO();
        vo.setId(user.getId());
        vo.setUsername(user.getUsername());
        vo.setRealName(user.getRealName());
        vo.setStatus(user.getStatus());
        vo.setCreatedAt(user.getCreatedAt());
        SysUserRole userRole = sysUserRoleMapper.selectOne(
                new LambdaQueryWrapper<SysUserRole>().eq(SysUserRole::getUserId, user.getId()));
        if (userRole != null) {
            SysRole role = sysRoleMapper.selectById(userRole.getRoleId());
            if (role != null) {
                vo.setRoleCode(role.getRoleCode());
                vo.setRoleName(role.getRoleName());
            }
        }
        return vo;
    }

    @Override
    public void save(UserSaveDTO dto) {
        Long count = sysUserMapper.selectCount(
                new LambdaQueryWrapper<SysUser>().eq(SysUser::getUsername, dto.getUsername()));
        if (count > 0) {
            throw new BusinessException("用户名已存在");
        }
        SysUser user = new SysUser();
        user.setUsername(dto.getUsername());
        user.setPassword(passwordEncoder.encode(dto.getPassword()));
        user.setRealName(dto.getRealName());
        user.setStatus(dto.getStatus() == null ? 1 : dto.getStatus());
        sysUserMapper.insert(user);
        // insert 后 MP 已把自增主键回填到 user，直接用 user.getId()
        saveUserRole(user.getId(), dto.getRoleId());
    }

    private void saveUserRole(Long userId, Long roleId) {
        if (roleId == null) {
            return;
        }
        SysUserRole userRole = new SysUserRole();
        userRole.setUserId(userId);
        userRole.setRoleId(roleId);
        sysUserRoleMapper.insert(userRole);
    }

    @Override
    public void update(UserSaveDTO dto) {
        SysUser user = sysUserMapper.selectById(dto.getId());
        if (user == null) {
            throw new BusinessException("用户不存在");
        }
        user.setRealName(dto.getRealName());
        if (dto.getStatus() != null) {
            user.setStatus(dto.getStatus());
        }
        sysUserMapper.updateById(user);
        // 角色更新：先删旧关联，再插新关联（本篇最重要知识点）
        if (dto.getRoleId() != null) {
            sysUserRoleMapper.delete(
                    new LambdaQueryWrapper<SysUserRole>().eq(SysUserRole::getUserId, dto.getId()));
            saveUserRole(dto.getId(), dto.getRoleId());
        }
    }

    @Override
    public void delete(Long id) {
        // @TableLogic 生效后，实际执行 UPDATE ... SET deleted=1
        sysUserMapper.deleteById(id);
    }

    @Override
    public void changeStatus(Long id, Integer status) {
        SysUser user = sysUserMapper.selectById(id);
        if (user == null) {
            throw new BusinessException("用户不存在");
        }
        user.setStatus(status);
        sysUserMapper.updateById(user);
    }

    @Override
    public void resetPassword(Long id) {
        SysUser user = sysUserMapper.selectById(id);
        if (user == null) {
            throw new BusinessException("用户不存在");
        }
        user.setPassword(passwordEncoder.encode("123456"));
        sysUserMapper.updateById(user);
    }
}
```

### 代码 5　统一响应体与全局异常处理

```java
public class R<T> {
    private Integer code;      // 200 成功
    private String message;    // 提示信息
    private T data;            // 数据

    public static <T> R<T> success(T data) {
        R<T> r = new R<>();
        r.code = 200;
        r.message = "success";
        r.data = data;
        return r;
    }

    public static <T> R<T> error(Integer code, String message) {
        R<T> r = new R<>();
        r.code = code;
        r.message = message;
        return r;
    }
}
```

```java
@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public R<Void> handleBusinessException(BusinessException e) {
        log.warn("业务异常：{}", e.getMessage());
        return R.error(e.getCode(), e.getMessage());
```

### 6.3 测试中发现的问题与处理

**问题一：接口返回 403 且响应体为空**

现象：在 Apifox 中调用 `GET /user/page`，返回 HTTP 403，**响应体完全空白**，看不到任何 `{code, message}` 提示，误以为接口未实现或服务宕机。

排查过程：

1. 用 `GET /hello` 探活，返回 200，说明服务正常；
2. 查看后端控制台，SQL 日志只打印了登录鉴权相关的查询，`/user/page` 一条 SQL 都没打，说明请求根本没进 Controller；
3. 检查 `SecurityConfig`，发现只放行了 `/auth/login` 与 `/hello`，其余全部 `anyRequest().authenticated()`；
4. 检查请求头，确认 Apifox 中未携带 `Authorization`。

原因定位：未携带令牌时，请求被 Spring Security 在过滤器链中拦截。由于 `SecurityConfig` 未配置自定义的 `AuthenticationEntryPoint`，Spring Security 6 默认使用 `Http403ForbiddenEntryPoint`，因此返回 **403 状态码且响应体为空**，而不是 `R.error(401, ...)`。

处理方式：在 Apifox 的 Headers 中添加 `Authorization: Bearer <token>`，接口恢复正常。同时明确后续优化方向：应配置统一的 `authenticationEntryPoint`，让未认证请求返回 `{"code":401,"message":"未登录或登录已过期"}`，避免同样的问题再次发生。

**问题二：用户列表中「角色」列显示为空**

现象：页面中 admin 显示「管理员」，而 teacher01、teacher02、student01 的角色列为空。

排查：检查数据库 `sys_user_role`，发现这几条用户只有 `sys_user` 记录，**没有对应的角色关联记录**，因此 `UserVO` 中 `roleCode` / `roleName` 为 `null`，前端渲染为空白。

结论：属于**初始数据不完整**，而非代码缺陷——接口逻辑按设计正确返回了空角色。处理方式：通过编辑功能为这些用户补充角色，或在 `schema.sql` 中补全种子数据。

**问题三：Apifox 中路径带 `/api` 前缀导致 404**

现象：参照浏览器 Network 面板的请求地址 `http://localhost:5173/api/user/page` 在 Apifox 中测试失败。

原因：前端 `baseURL` 为 `/api`，该前缀是给 Vite 代理用的，`vite.config.js` 中的 `rewrite` 会在转发前把 `/api` 去掉。因此直接请求后端时应使用 `http://localhost:8080/user/page`，不带 `/api`。

处理方式：Apifox 中统一使用 `http://localhost:8080` 为基地址，接口路径不含 `/api`。

> ✎ 这一节是**整份报告最有价值的部分**。把 403 的排查过程写清楚（尤其「SQL 一条没打 → 请求没进 Controller」这个判断），老师能看出你真的在调试，而不是碰巧跑通。同理，「角色列为空」主动解释清楚，能直接把一个潜在扣分点变成加分点。

## 七、总结与体会

### 7.1 本次作业完成情况

本次作业完成了用户管理模块的 7 个后端接口、JWT 鉴权链路与前端页面联调，全部用例测试通过。相比原型阶段的纯前端模拟，本次改动让系统第一次具备真实的数据持久化与访问控制能力。

### 7.2 主要收获

**（1）理解了「认证」与「授权」的区别。** 认证解决「你是谁」，授权解决「你能做什么」。本次作业实现的是认证层：过滤器验签成功后只是把身份写入 `SecurityContext`，具体哪个角色能访问哪个接口，还需要后续用 `hasRole()` 或方法级注解 `@PreAuthorize` 来补。这一点在做完「登录成功但接口仍 403」的排查后理解得格外清楚。

**（2）理解了过滤器链的执行顺序。** 自定义过滤器必须通过 `addFilterBefore(..., UsernamePasswordAuthenticationFilter.class)` 挂到正确位置，否则会在 Spring Security 的授权判断之后才执行，导致即使带了合法令牌也依然被拒绝。调试 403 问题时，正是靠「SQL 没打印」反推出请求压根没进入业务层。

**（3）MyBatis-Plus 在提升效率的同时也带来了隐式行为。** `@TableLogic` 让删除一行代码就变成逻辑删除，非常方便；但也意味着「写自定义 SQL 时要记得自己加 `deleted = 0`」，否则被删数据会重新出现。同理，`Page` 泛型转换时 `total` 需要手动搬运，这类「看起来能跑、其实丢了数据」的坑，比报错更难发现。

**（4）前后端联调的关键是约定一致。** 本次遇到的 `/api` 前缀问题、请求头格式问题，本质都是前后端约定没有对齐。`Authorization: Bearer <token>` 中 `Bearer` 后的**一个空格**、令牌不能带引号和换行，这些细节一旦出错，服务端只会静默地不做认证，排查成本很高。后续应当把接口文档作为唯一事实来源，联调前先对照文档自查。

### 7.3 存在的问题与改进方向

1. **未认证请求的响应不规范。** 目前返回 403 且无响应体，前端无法区分「未登录」与「无权限」，也无法触发跳转登录页。应配置 `AuthenticationEntryPoint` 与 `AccessDeniedHandler`，分别返回 401 与 403 的结构化信息。
2. **角色关联采用一对一实现。** 当前 `toVO` 用 `selectOne` 查询，一个用户只能有一个角色。若业务需要多角色，需改为 `selectList` 并返回角色列表，前端表格也要相应支持多标签展示。
3. **接口级授权尚未实现。** 目前只要登录即可调用所有 `/user/**` 接口，学生账号理论上也能访问用户管理接口。应补充 `@PreAuthorize("hasRole('ADMIN')")` 等授权规则。
4. **列表查询存在 N+1 问题。** 每条用户记录都要单独查一次关联表和角色表，数据量大时性能不佳。可改为一次性查出 `userId` 列表后批量关联查询。
5. **初始数据不完整。** `sys_user_role` 缺少部分用户的角色记录，应补齐种子数据，避免前端展示异常。

### 7.4 心得体会

这次作业最大的体会是：**「能跑通」和「能用」之间隔着一整轮调试。** 前端点登录能进首页的时候，我以为接口已经好了；直到用 Apifox 单独测接口，才发现不带令牌全是 403。如果只在前端点页面，这个漏洞根本发现不了——因为前端拦截器会默默帮我加上令牌。这让我意识到，接口测试不能只依赖前端页面，必须用独立工具直接验证接口本身的行为，尤其是异常分支。

另一个体会是关于「定位问题的方法」。403 那一次，我先怀疑令牌过期，又怀疑角色前缀写错，试了半天没有结果。最后是回头看后端控制台——发现一条 SQL 都没有打印，才反应过来请求没进业务代码，问题一定在过滤器链上。**先确认「请求走到了哪一步」，比猜测「哪里写错了」高效得多。** 这一点对以后排查任何跨层问题都适用。

> ✎ 这一节别写成套话。判断标准很简单：**如果把项目名换掉还能原样用，那就是套话。** 上面 7.2 的四个收获都绑定了具体的技术细节和踩过的坑，7.3 列出的都是真实存在的短板（而且你能说清怎么改），老师会觉得你确实读懂了代码。7.4 的心得围绕「只在前端页面验证发现不了 403」这个真实经历展开，是整篇最有说服力的部分。
