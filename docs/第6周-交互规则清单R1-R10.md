## 一、分类管理页（R1~R6）

### R1 新增分类时名称必填，且提交前 trim

触发：点「新增分类」或节点上的「新增子分类」→ 填名称 → 确定
行为：名称为空或全空格时提示「请输入分类名称」，不发请求
位置：CategoryList.vue handleSave()

### R2 提交时 parentId 归一为 0

触发：新增顶级分类时不选上级，或新增后手动清空上级下拉
行为：el-tree-select 清空后值为 null，提交前用 form.parentId ?? 0 归一为 0；且先复制一份再改，不动与界面绑定的 form
原因：后端约定 parent_id = 0 表示顶级，传 null 会让同级重名校验失效（eq 匹配不到任何行）
位置：CategoryList.vue handleAdd() / handleSave()

### R3 编辑分类的唯一性校验必须排除自己

触发：编辑某个分类，只改排序、不改名称
行为：允许保存，不报「同级分类名称已存在」
位置：后端 QuestionCategoryServiceImpl.update() 的 ne(getId, 自己)

### R4 编辑分类时上级分类候选排除自己及后代

触发：编辑「计算机网络」，展开上级分类下拉
行为：下拉里不出现自己，也不出现自己的子分类；后端另有兜底校验，拒绝形成环
原因：若把自己挂到自己的后代下，buildTree 永远遍历不到这一支，节点会从树上静默消失
位置：CategoryList.vue parentOptions 计算属性；QuestionCategoryServiceImpl.checkParent()

### R5 删除分类前必须二次确认，拦截逻辑交给后端

触发：点节点上的「删除」
行为：弹确认框；有子分类 → 「该分类下有子分类，请先删除子分类」；有题目 → 「该分类下有题目，无法删除」；都没有才物理删除
说明：前端不做预判断，因为「有没有子分类/题目」只能查库得到，让后端拒绝后由响应拦截器统一弹提示
位置：CategoryList.vue handleDelete()；QuestionCategoryServiceImpl.delete()

### R6 点节点文字不折叠，点按钮不改变选中态

触发：点击节点文字 / 点击行内三个按钮
行为：文字点击不展开折叠；点按钮只触发对应动作，不改变树的选中态
位置：CategoryList.vue 的 :expand-on-click-node="false" + 三个按钮的 @click.stop

## 二、题目管理页（R7~R10）

### R7 切换题型时联动重置答案区

触发：在新增/编辑对话框里切换题型
行为：清空单选答案、多选答案、判断题答案、填空题空值，并把 form.answer 置空；切到选择题时初始化 A~D 四个空选项
位置：QuestionList.vue onTypeChange()

### R8 单选答案只列出「已填写内容」的选项

触发：单选题里只填了 A、B 两个选项的内容
行为：答案区只出现 A、B 两项，未填内容的 C、D 不出现
原因：避免用户把答案选到内容为空的选项上，产生脏数据
位置：QuestionList.vue filledOptions 计算属性

### R9 保存时按题型组装 options 与 answer

触发：点对话框「确定」
行为：
- 单选/多选：options = 仅保留已填内容选项的 JSON 字符串；answer 单选取 singleCorrect，多选取 multiCorrect 排序后逗号拼接
- 判断：options 不传（落库为 NULL）；answer 取 A（对）或 B（错）
- 填空：options 不传；answer 为过滤掉空值后的逗号拼接
- 简答：answer 为整段文本
补充校验：答案必须对应「已填写内容」的选项，否则提示并不发请求
位置：QuestionList.vue handleSave()

### R10 保存成功后重新拉取数据

触发：新增/编辑/删除成功后
行为：关闭对话框并重新调用 loadData() / loadTree()，不采用「本地改那一行」的做法
原因：分页、筛选、排序、total 都由后端算，本地改容易与服务端不一致
位置：QuestionList.vue 各操作成功后；CategoryList.vue handleSave() / handleDelete()
